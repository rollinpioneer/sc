# Stage 1 changes

- The system Conda configuration redirects the `nvidia` channel to an unavailable mirror (HTTP 404). The curation environment therefore uses an official PyTorch CUDA wheel instead of the prescribed Conda `pytorch-cuda=11.8` package. This changes only package delivery; training configuration and model remain unchanged.
- Stage 1 adds standalone HDF5 schema inspection, scoring, transition-score export, and raw chunk-evidence export interfaces. Official SCIZOR model inference and `Evaluator.rank_prob_to_score` are reused without alteration.
- Official `accelerate_train_one_loader.py` imports NVIDIA DALI before selecting a dataset and fails before HDF5 data loading. `stage1/src/train_hdf5_baseline.py` is the documented HDF5-only entrypoint: it reuses `HDF5Dataset`, `Discriminator`, AdamW, OneCycleLR, rank loss, and all specified baseline hyperparameters while omitting only the unused DALI/OXE/ZMQ pipeline.
- Minimal upstream HDF5 patch: `hdf5_dataset.py` now carries the byte-for-byte-equivalent `normalize_images` implementation instead of importing `curation.utils`, whose unrelated W&B/Flax/OXE logging imports prevented the HDF5 dataset from loading. No data transform, model, loss, or optimizer behavior changed.
- The initial unpinned Transformers 5.16 build ran an abnormally long CUDA kernel on the first batch. Stage 1 pins the compatible PyTorch `transformers==4.40.2`; `USE_TF=0` and `TRANSFORMERS_NO_TF=1` prevent its unused image utilities from importing an incompatible TensorFlow build. This preserves the original DINOv2 PyTorch backbone.
- Minimal scorer import patch: `suboptimal_hdf5.py` now localizes the same image normalization and visualization color overlay previously imported through TF/OXE utility modules. `Evaluator`, `Inference`, and particularly `Evaluator.rank_prob_to_score` remain unmodified.
